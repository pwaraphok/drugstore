# เภสัชพร้อม — ระบบร้านยาสำหรับทดสอบในเครื่อง

ระบบทำงานจริงกับ MariaDB พร้อมหน้าจอภาษาไทย รองรับขายเงินสด คลังล็อต รับเข้า คืนสินค้า และงานเภสัชกรพื้นฐาน ข้อมูลปัจจุบันเป็นข้อมูลสาธิตและรายการทดสอบ ไม่ใช่ระบบที่ตรวจรับสำหรับผู้ป่วยจริงครบทุกข้อใน drugstore.v2.md

## เปิดใช้งาน

1. เปิด Docker Desktop
2. ดับเบิลคลิก **เปิดระบบ.cmd** ในโฟลเดอร์นี้ (ถ้าระบบเปิดอยู่แล้วไม่ต้องเปิดซ้ำ)
3. เข้า http://127.0.0.1:3000
4. ใช้บัญชีใน `.local-credentials.txt` เก็บไฟล์นี้เป็นความลับ

ปิดหน้าต่างที่เปิดระบบเพื่อหยุดเว็บและ API ฐานข้อมูลยังเก็บใน Docker volume ไม่ต้องลบ container หรือ volume หากต้องการเก็บประวัติ

## ขั้นตอนทดลอง

1. เปิดกะเงินสดและกะเภสัชกรจากหน้าภาพรวม
2. เลือกสินค้าใน **ขายและจ่ายยา** กำหนดหน่วย จำนวน และคำแนะนำ
3. ตรวจข้อมูลผู้รับบริการและประวัติแพ้ยา ให้เภสัชกรทบทวนและบันทึกเหตุผล
4. จองล็อต รับเงินสด และยืนยันส่งมอบ ระบบตัดยอดและต้นทุนในธุรกรรมเดียว
5. เปิด **ประวัติการขาย** เพื่อพิมพ์ใบเสร็จ รับคืนเข้ากักกัน หรือคืนเงินด้วยสิทธิ์ผู้จัดการ
6. **รายงานและตรวจสอบ** แสดงบิลรับเงินแล้วรอส่งมอบ ยอดสต็อกต่าง และงานฉลาก ต้องยืนยันว่ากระดาษออกจริงด้วยตนเอง

สินค้าที่เรียกคืน หมดอายุ หรือถูกกักกันไม่สามารถจองขายได้ ข้อมูลคลินิกอัตโนมัติจะแสดงความครอบคลุมไม่ครบและกำหนดให้เภสัชกรทบทวนเสมอ ไม่แสดงคำรับรองว่าปลอดภัย

## สิ่งที่ทำได้

- สินค้า หน่วย บรรจุภัณฑ์ บาร์โค้ด ราคาตั้งต้น สารสำคัญ ผู้จำหน่าย และตำแหน่งเก็บ
- ใบสั่งซื้อ อนุมัติ รับบางส่วน รับโดยไม่มีใบสั่งซื้อพร้อมเหตุผล ตรวจการรับเกิน
- ล็อต/วันหมดอายุ FEFO การจอง ย้ายตำแหน่ง กักกัน ตรวจนับปรับลด และบันทึกทำลาย
- ขายเงินสด เงินทอน คืนเงินบางส่วน ป้องกันคำขอซ้ำ และตรวจยอดชำระสุทธิหลังคืนเงิน
- รับคืนอ้างอิงล็อตที่ขายและรับเข้ากักกัน พร้อมคืนชั้นต้นทุน
- ผู้รับบริการ ประวัติแพ้ยา ยาปัจจุบัน บันทึกการให้บริการ และการทบทวนก่อนจ่าย
- บัญชีผู้ใช้ตามบทบาท ระงับบัญชี การตรวจใบอนุญาตโดยผู้จัดการ กะเภสัชกร/เงินสด และประวัติการทำรายการ
- บันทึกหลักฐานอุณหภูมิ SOP การอบรม ข้อร้องเรียน การแก้ไข และคำขอข้อมูลส่วนบุคคล
- ฉลากพร้อมข้อมูลผู้รับบริการ/ผู้จ่ายที่บันทึก ณ เวลาขาย งานพิมพ์ซ้ำไม่ตัดสต็อก

## สำรองข้อมูลและทดสอบกู้คืน

จากโฟลเดอร์นี้ใช้ `npm run backup` ได้ไฟล์ SQL และค่า SHA-256 ใน `backups/` ควรสำรองก่อนอัปเกรดและหลังปิดร้าน เก็บสำเนาเข้ารหัสนอกเครื่องตามนโยบายร้าน

`npm run backup:verify` ตรวจ checksum กู้คืนไฟล์ล่าสุดลงฐานข้อมูลใหม่ชื่อ `drugstore_restore_<เวลา>` และตรวจยอดสต็อกกับบัญชีเคลื่อนไหว ไม่เขียนทับฐานข้อมูลร้าน ฐานข้อมูลทดสอบถูกเก็บไว้ให้ตรวจสอบ

ไฟล์สำรองมีข้อมูลส่วนบุคคลเมื่อใช้ข้อมูลจริง จึงต้องจำกัดผู้เข้าถึง สคริปต์นี้สำรองเฉพาะฐานข้อมูล ไม่รวม `.env`, รหัสผ่าน, ไฟล์แนบ หรือโปรแกรม ไม่ได้ตั้งเวลาสำรองอัตโนมัติหรือยืนยัน RPO/RTO

## สำหรับผู้ดูแลระบบ

ใช้ Node.js 20 ขึ้นไป (แนะนำรุ่น LTS ที่รองรับ), npm และ Docker Desktop

```powershell
npm install
docker compose up -d mariadb
npm run migrate
npm run build
npm start
```

เครื่องใหม่ต้องคัดลอก `.env.example` เป็น `.env` กำหนด JWT_SECRET สุ่ม และ DB_PORT=3307 ก่อนเริ่ม กำหนด SEED_PASSWORD อย่างน้อย 12 ตัวแล้วใช้ `npm run seed` เฉพาะฐานว่างสำหรับข้อมูลสาธิต การ seed ไม่รีเซ็ตฐานเดิมและถูกปิดเมื่อ NODE_ENV=production

`npm run dev` เปิดเว็บและ API พร้อมกันสำหรับพัฒนา `npm test` ใช้ฐานข้อมูลและ API ที่กำลังเปิดอยู่ สร้างสินค้าทดสอบแยกและคงเอกสารประวัติไว้ ห้ามรันบนฐานข้อมูลจริง

เว็บ/API/ฐานข้อมูลเปิดเฉพาะ loopback ของเครื่อง (3000/3001/3307) การแก้ให้ใช้งานผ่านเครือข่ายต้องออกแบบ TLS, secret management, firewall และการควบคุมสิทธิ์เพิ่มเติม ค่า DB ใน compose ปัจจุบันเป็นค่าเฉพาะชุดสาธิต

โครงสร้าง: `apps/web` หน้าจอ Next.js, `apps/api` NestJS, `apps/api/src/database/migrations` การปรับฐานข้อมูล, `scripts/integration.cjs` การทดสอบธุรกรรม
